# Development instructions

- Verify existing code and progress before changing anything. Preserve completed work.
- Implement the next logical milestone, test and debug it, and commit stable progress.
- Do not deploy, publish, incur expenses, or activate paid services without user approval.
- This project is included in the user's Develop trigger alongside their other projects.
- Prefer regular chat mode; explain when Work mode offers a clear advantage. The app mode must be selected by the user.
- Build toward comprehensive worldwide coverage. Do not claim to be the largest without evidence.
- Distinguish proposed collections from verified published records. Every published record needs sources and editorial review.
- Keep payment integration, server-enforced entitlements, and content eligibility explicit; no simulated checkout presented as real.
- Keep credentials, restricted evidence, private personal data, and payment details out of Git.
- Verify content rights, provenance, and appropriate access controls before adding restricted material.
